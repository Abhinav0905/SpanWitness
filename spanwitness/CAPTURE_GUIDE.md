# Independent demo footage

The fastest useful next dataset is a tabletop scene that you can label honestly. Keep it distinct from field validation.

## Record these four short clips

1. Two upright cardboard or wooden model poles with dark thread between them. Put a leafy plant behind the thread. Move the phone sideways so the apparent overlap changes.
2. Keep a leafy object visually overlapping the thread in both selected views. Describe the result as persistent projected overlap, not verified physical contact.
3. Put a visible interruption in an isolated piece of dark thread. Include a second case with an intact thread hidden by an object. The prototype should not claim it can diagnose the difference.
4. Put an upright model pole beside a clearly vertical reference in the same plane. Rotate the phone, then repeat with the model pole tilted. Record which model is actually upright.

Use normal indoor light and a plain background. Include a blurred image and a low-contrast image. Export still frames as JPEG or PNG for the current upload interface; the browser camera can sample live frames too.

Keep the raw clips, the selected frames and a small annotation table. Record clip ID, frame time, visible condition, marked path or axes, and expected next action. Collect some clips after the thresholds are frozen so they are separate from tuning.

These recordings can validate a constrained demonstration. They cannot establish utility-grade defect detection or physical clearance accuracy. Actual utility imagery needs suitable rights, expert labels and a separate evaluation.
